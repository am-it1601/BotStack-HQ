BotStackHQ — Phase 1 Critical Data Flows

ComplianceStack MVP · CipherCru Innovations · 2026 · AWS ap-south-1 (Mumbai)

Flow 1 — Inbound Client Message (WhatsApp)
Client sends a message — query, reply, or document — via WhatsApp. Agent processes and responds.
1
Client sends WhatsApp message
Text query, document upload, or reply to input collection request
2
Meta API → API Gateway webhook handler
Signature verified (X-Hub-Signature-256). Timestamp validated — events older than 5 min rejected
3
Webhook Handler Lambda — classify intent
textdocumentstatus update
4
Enqueue → SQS LLM inference queue
Message routed for AI agent processing. Visibility timeout: 300s
5
AI Agent Lambda → LangChain.js → GPT-4o
pgvector RAG retrieval if knowledge base context needed. Claude Sonnet fallback for complex queries
6
Response generated → SQS WhatsApp dispatch queue
Conversation state written to RDS PostgreSQL. Token usage logged
7
Notification Lambda → Meta WhatsApp API → Client
Message delivered. Delivery receipt logged to RDS
8
WebSocket push → CA dashboard
New client message visible in conversation monitor in real-time
Flow 2 — Filing Calendar Trigger (Automated)
EventBridge fires at the configured lead time before a filing deadline. Agent collects inputs from client automatically — no CA intervention needed unless client is unresponsive.
1
EventBridge Scheduler fires — T-12 days before deadline
One-time schedule per client per filing. Created automatically at client onboarding
2
Workflow Engine Lambda triggered
Fetch client filing config, WhatsApp number, and filing type details from RDS
3
AI Agent generates input collection message
Filing-type specific: GSTR-1 requests sales register; GSTR-3B requests ITC details and purchase data
4
SQS WhatsApp dispatch → Notification Lambda → Client
Meta pre-approved template message sent. Delivery confirmed
5
Workflow state updated in RDS
Status: input_requested. Next EventBridge trigger scheduled: T-7 days
6
T-7 reminder fires if no client response
Gentle reminder dispatched via WhatsApp. T-3 escalation trigger scheduled
7
T-3 escalation — CA notified + urgent client reminder
CA receives dashboard alert and WhatsApp notification. Client gets urgent reminder message
8
Client responds → inputs collected → CA notified
Workflow state: inputs_complete. CA dashboard alert. Ready to file
Flow 3 — Document Upload from Client
Client uploads a PDF (GST certificate, TDS certificate, invoice) via WhatsApp. Document AI extracts structured fields and validates completeness.
1
Client sends PDF via WhatsApp
GST certificate, TDS certificate, invoice, or other compliance document
2
Webhook Handler downloads media from Meta API
Authenticated download using media URL from webhook payload
3
File uploaded to S3
Key pattern: workspaces/{workspace_id}/clients/{client_id}/filings/{filing_id}/{filename}
4
S3 key written to RDS document record
Status: uploaded, awaiting_extraction
5
SQS document processing queue → Python FastAPI Lambda
Document AI service triggered. Container Lambda with 3GB memory, 300s timeout
6
Field extraction — GSTIN, ARN, turnover, period, TDS amounts
PyMuPDF + pdfplumber for text PDFs. pytesseract OCR for scanned documents
7
Validate against filing checklist
All required fields present? Values plausible? Filing period matches expected? GSTIN format valid?
8
If incomplete → Notification Lambda → client (missing fields)
Agent sends specific list of missing or incorrect fields. Client re-uploads
9
If complete → CA notified — inputs ready to file
Dashboard alert + structured data summary. WebSocket push updates filing status live
Flow 4 — Post-Filing Confirmation
CA files the report on the government portal (external action), then marks it complete in BotStackHQ. Agent automatically sends a confirmation to the client with ARN and filing details.
1
CA files report on GST / TDS portal (external action)
CA acts outside BotStackHQ on the government portal. This is a licensed professional act
2
CA marks filing complete on dashboard
Enters ARN number and filing date in BotStackHQ dashboard
3
API Handler Lambda updates filing record in RDS
Status: filed. ARN, filing date, and CA user ID recorded with timestamp
4
Workflow Engine triggered — filing confirmed event
Confirmation workflow initiated for this client + filing combination
5
Confirmation Agent generates message
Personalised per client — includes ARN, filing type, period covered, date filed
6
SQS WhatsApp dispatch → Notification Lambda → Client
Filing confirmation delivered to Mr X via WhatsApp. Delivery receipt logged
7
Immutable audit log entry written to RDS
Timestamp, workspace_id, user_id, ARN, delivery status — full trail, append-only
8
WebSocket push → CA dashboard — status: confirmed
Filing turns green. Cycle complete. No reverse follow-up needed from client
